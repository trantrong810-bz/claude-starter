# Split docs/WORKFLOW.md into separate files in docs/workflows/

> Historical plan (ADR 0018), translated to English by ADR 0020R. File names, front matter keys and messages are quoted as they were at the time; ADR 0020R renamed them (for example `tong-quan.md` → `overview.md`, `thu-tu` → `order`).

## Context

`docs/WORKFLOW.md` collects 6 workflows (5 Mermaid diagrams and 1 table) in one long file. Each workflow will get its own file in `docs/workflows/`. `WORKFLOW.md` becomes an index **generated** from the files' front matter, and `verify --quick` fails when the index drifts, like `adr.mjs` does. Adding a workflow later only means creating a file and running `node scripts/workflow.mjs index`; if forgotten, verify reports it.

## 2. scripts/workflow.mjs (new, following the scripts/adr.mjs pattern)

- `parse` / `load`: reuse exactly the approach of [adr.mjs:21-42](scripts/adr.mjs#L21-L42) (normalize CRLF, read front matter with a regex, skip `README.md` and `_*`). Sort by `thu-tu`, then by file name.
- `renderIndex`: generates `docs/WORKFLOW.md` with:
  - a title and the line "generated by `node scripts/workflow.mjs index` — do not edit."
  - the reminder "Changing a command, hook, subagent or the task classification rule → update the diagram in `docs/workflows/` in the same commit."
  - "Yellow boxes are the points where you need to be present."
  - a `| # | Workflow | Description |` table linking to `workflows/<file>.md`
  - the line "New workflow: copy `workflows/_template.md` to `workflows/<name>.md`, fill it in, then run `node scripts/workflow.mjs index`."
- `check`: file names are kebab-case ASCII; front matter exists; `thu-tu` (a number), `tieu-de` and `mo-ta` are present; `thu-tu` is unique. The index matches `renderIndex`, compared through `norm()` that ignores table alignment (copied from [adr.mjs:114-124](scripts/adr.mjs#L114-L124)). Errors print a `WORKFLOW` error header with the list, then `exit 1`.
- CLI: `index | check`.
